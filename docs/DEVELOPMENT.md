# Safehouse · 求生之路 2 本地管理器

Windows 10/11 x64 桌面客户端，采用 Miuix / HyperOS 的视觉风格。界面使用 Electron 与 HTML/CSS 实现，并非 Compose Miuix 组件的原生移植。

## 安装与直接运行

推荐双击 `Safehouse-Setup-0.1.15-x64.exe`。NSIS 安装器使用当前用户模式，不请求提权，可选择目录并创建开始菜单 / 桌面快捷方式；默认位于当前用户的 Programs 目录。卸载仅移除应用和快捷方式，保留 `%APPDATA%\Safehouse` 与游戏文件。升级继续使用原安装目录。

完整解压 `Safehouse-0.1.15-win-x64.zip`，双击根目录的 `Safehouse.exe`。无需安装 Node.js，启动清单使用普通用户 `asInvoker`，不请求管理员权限。首次运行会将应用复制到 `%LOCALAPPDATA%\Safehouse\versions`，之后打开已准备好的版本。若旧缓存及其子目录不可写，运行副本会改用 `%TEMP%\Safehouse-runtime\versions`；设置仍保存在原来的永久用户目录。启动器为原生 Windows EXE，不依赖 PowerShell 或 CMD。启动日志位于所用缓存根目录的 `launcher.log`；未签名版本仍可能显示 Windows 发布者提示。`Start Safehouse.cmd` 只是同一 EXE 的备用入口。测试新版前请关闭仍以管理员身份运行的旧版，以免旧版占用单实例锁。

0.1.2 修正本机发布目录继承的 Low mandatory label：旧 EXE 实际以低完整性运行，写入 AppData 被 Windows 拒绝，因此看起来需要管理员权限。打包脚本仅将自己生成的启动器和应用 EXE 标记为 Medium，不修改工作区或系统目录 ACL，不关闭 UAC。ZIP 不携带 NTFS 完整性标签；建议完整解压到正常的用户文件夹。

启动后会自动扫描 Steam 游戏库。未找到游戏时，在「偏好设置 → 选择目录」中选择 `Left 4 Dead 2`，或其中的 `left4dead2` 文件夹。应用不会自动启动或重启游戏。

## 已实现

- 识别 Windows 注册表中的 Steam 目录、`libraryfolders.vdf` 和 App 550 安装清单；扫描游戏 `left4dead2/addons`、`addons/workshop` 与 Steam 工坊缓存。
- 战役地图、幸存者、武器、感染者、物品 / 投掷物、音效 / 音乐、界面、脚本与其他内容分类；按名称、具体角色或枪械搜索，支持按替换目标排序、网格/列表视图、本地包封面与详情。
- 拖入或选择 VPK / ZIP 安装；ZIP 内的 VPK 一起预检，遇到同名文件整批拒绝覆盖。安装队列显示校验、实际复制进度、失败、取消、重试和持久化记录。
- 单项和批量启停，写入游戏实际使用的 `left4dead2/addonlist.txt`；批量卸载移至系统回收站。
- 读取本机 Steam `config/loginusers.vdf`，显示已登录账号、SteamID 和客户端运行状态；不嵌入 Steam 网页登录，也不保存 Web Cookie。
- Steam 创意工坊关键词、ID、官方链接搜索，客户端内订阅、下载、取消订阅；按战役地图、战役、武器、角色、皮肤、音效、界面、脚本等社群分类筛选；查看项目详情并翻译公开标题和详情。
- 社区标题和详情自动翻译到系统语言，支持修改目标语言、查看原文、翻译缓存及失败原因；浅色、深色及跟随系统主题。

## 内容分类与替换目标（0.1.3）

- 幸存者细分为 Nick、Rochelle、Coach、Ellis、Bill、Zoey、Francis、Louis 八个游戏替换槽位，显示中英文角色名和数量。
- 武器按手枪、冲锋枪、霰弹枪、突击步枪、狙击枪、重型武器、近战筛选，再选择 M16、AK-47、UZI、SPAS、M60 或具体近战等实际槽位。投掷物、医疗物品与感染者也有单独的细分类。
- 根据包内模型、材质、语音、武器脚本路径识别目标；`models/weapons/arms` 属于角色手臂，不能因此认定为武器。完整战役携带的模型等资源保持战役分类，元信息只在实际资源不足以识别时补充。无法确认的目标明确显示未识别 / 未细分。
- 同一包可出现在多个实际目标下。卡片直接展示目标，详情显示识别用到的资源路径；点击目标可集中查看对应内容。数量区分已安装与已启用，不把 Steam 缓存视为已启用。
- 「只看同目标多项启用」帮助集中查看替换范围重叠的内容；它不是独立冲突检测页面，也不把同一角色不同组成部分直接判为确定冲突。可用原有单项 / 批量启停逐项对照。

## 模组管理与工坊整合（0.1.4）

- 「我的内容」更名为「模组管理」，移除独立的「下载与安装」导航。模组管理显示全部任务，创意工坊显示工坊任务；进度、失败重试、取消和清理记录在当前页面操作。
- 两个页面的工坊模组卡片都提供订阅状态、订阅 / 取消订阅和详情按钮；本地导入且没有工坊 ID 的包显示「本地模组」。订阅状态来自 Steam，与启停开关分开。
- 取消订阅成功后停止该项目的排队 / 复制任务，并将其游戏 addons 中的全部对应副本移至回收站。Steam 取消失败时不删除文件；文件被占用等卸载失败会明确提示。仅移除相同工坊 ID 的副本，不操作其他模组或 Steam 原始缓存。
- 创意工坊增加角色、武器类型、感染者、医疗物品及玩法等细分类；直接使用 Steam 社群标签，查询会在服务器端带上父级和子级条件。公开浏览只读取当前结果集，避免把推荐卡片混入分类结果。

## 中英文搜索与中心控制台（0.1.5）

- 模组管理和创意工坊支持中英文自适应搜索。例如“初音”会联查 `Hatsune Miku`，“尼克 女仆”关联 `Nick maid`。内置角色、枪械、战役与常用 Mod 词库；复合搜索词共同匹配，避免只命中一个宽泛词。
- 不在词库中的搜索词通过已有在线翻译服务生成另一语言的查询。只发送用户输入的搜索词，不上传本地文件内容、模组清单或账号凭据。在线翻译短时不可用时，明确提示并使用原词和离线词库；标题自动翻译开关独立控制标题显示。
- 工坊保留原词和翻译词的结果，并按工坊 ID 去重；每个查询都携带当前社群分类和细分类，跨页不重复，返回上一页保留相同结果。关键词翻译短时缓存，合并结果缓存十分钟。
- 新增「中心控制台」，由用户填写自己的面板地址。在客户端内嵌入现有生还者控制台，继续使用原面板的地图、插件、下载、玩家及服务器管理功能；可以修改并保存完整 HTTP / HTTPS 地址。
- 面板运行在隔离沙箱中，网页没有 Node 或通用本地 API。0.1.7 的专用 preload 只适配面板已有的下载助手握手和下载请求，不向网页暴露文件路径、模组管理或任意 IPC。只允许当前面板站点内导航，外部链接使用宿主工具栏「浏览器打开」。不会自动启动、重启或修改远端服务器。
- 支持面板已有的 HTTP Basic 账号验证；在控制台登录栏输入面板账号和密码，密码只用于本次验证，不写入设置文件。0.1.7 起面板自身签发的 Cookie 与站点偏好保存在固定的客户端用户目录，重启与更换发布目录后继续有效，不复用浏览器凭据。HTTP 地址的连接本身不加密；已有 HTTPS 面板可直接填写 HTTPS 地址。
- 连接错误、HTTP 失败状态和超时显示明确原因并可重试。0.1.6 修正默认地址的协议：此面板使用 HTTPS，旧版误写为 HTTP。旧设置自动迁移到 HTTPS，保留路径和页面锚点；其他自定义 HTTP 面板地址保持原样。2026-10-27 客户端已加载真实面板登录页，线上服务器配置未改动。

## 工坊卡片分类标签（0.1.6）

- 搜索结果与项目详情显示中文分类、武器类型及具体替换槽位，例如 Nick · 尼克、UZI、M16、SPAS-12。依据作者 Steam 标签、标题或描述中的替换说明；已安装内容优先采用本地 VPK 资源识别结果。
- 明确的替换说明优先于模型宣传名称，避免把“AK47 模型替换 M16”标成 AK47。标题关键词推测以虚线和“推测”标注，悬停可查看标签来源；信息不足显示“具体槽位未注明”，不会把泛称 Rifle 强行归入 M16。

## 面板适配、直连下载与登录保持（0.1.7）

- 控制台默认折叠地址栏，压缩标题与留白；自动按可用宽度缩放，也可选择 70%–125%。「宽屏模式」隐藏管理器外侧栏，面板内部布局使用更大的可用空间，缩放设置保存在本机。
- 地图管理中点击「直连下载导出（推荐）」，再点击「下载到客户端」。不再需要浏览器扩展或复制命令，客户端直接从网盘传输文件；上方模组任务显示真实字节进度、取消、失败原因与结果。
- 文件保存至系统「下载」目录中的 `Safehouse` 文件夹，下载完成可打开文件夹或点击「安装到模组管理」。支持 VPK / ZIP，最大 2 GiB；安装仍经过原有 VPK 和 ZIP 检查，不覆盖现有同名模组。下载源来自当前面板或其百度 HTTPS 直链；签名链接只驻留内存，不写入任务记录。
- 直链过期、文件格式不符、大小不一致或连接空闲超时会显示失败，需从面板重新获取链接。取消会清理未完成文件，清理记录会保留已完成下载。普通服务器导出与插件下载不属于本次直连适配。
- 面板会话使用固定的 `persist:safehouse-center-console` 分区，数据位于 `%APPDATA%\Safehouse\Partitions`，与 EXE 发布目录分开。退出时刷新站点存储和 Cookie；更新版本不清理此目录；0.1.7–0.1.13 只保留 Cookie，不保存面板密码。0.1.14 的可选记住登录见下文。
- 0.1.6 及更早版本使用临时会话，已经丢失的登录记录无法恢复，升级后需重新登录一次。之后在服务器会话有效期内保留登录；服务器重启、会话到期、修改密码或主动退出后仍须重新登录。HTTP Basic 身份验证与面板自己的 Cookie 登录机制不同，Basic 密码不持久保存。

## 动态服务器连接卡片（0.1.8）

- 在左侧「中心控制台」导航下方显示服务器连接卡片，点击命令文本或复制图标，将完整的 `connect 游戏地址:端口` 复制到剪贴板。
- 地址取自当前内嵌面板展示的游戏连接命令或游戏地址字段，支持 IPv4、域名与带方括号的 IPv6；不将面板的 HTTP / HTTPS 端口当作游戏端口，也不固定使用 27015。
- 面板更新游戏地址时自动同步。更换面板、页面重新加载、退出登录或连接失败时清除旧地址；未提供有效地址时显示提示并禁用复制。读取连接信息不会执行游戏命令或启动游戏。
- 连接信息仅保存在当前运行内存中，网页不能主动写入剪贴板；复制仅由客户端按钮触发。无须输入或保存额外账号信息。

## 本地模组删除（0.1.9）

- 本地导入模组的卡片与详情页提供「删除」按钮，网格和列表视图均可使用。
- 删除前显示模组名称并确认，将游戏 addons 中的已安装副本移至系统回收站，原始导入 VPK / ZIP 保留。取消不会修改文件；删除失败会显示原因。
- 删除后自动刷新模组库、数量和选中状态；分卷 VPK 仍需在文件夹中处理。Steam 工坊项目继续使用「取消订阅」卸载，避免同步时自动下载。

## 本地化保留与失败任务清理（0.1.11）

- `core/localization.js` 负责本地化：预检整个工坊项目的已安装 VPK，通过流式复制和 SHA-256 生成独立文件，原子发布到 `addons/safehouse-local-工坊ID-内容摘要.vpk`。它不是指向 Steam 文件的链接。原工坊副本停用，新副本继承原启停状态；多 VPK 项目一并保留，相同内容不重复复制。
- `%APPDATA%\Safehouse\localized-mods.json` 保存游戏目录、来源工坊 ID、目标文件和摘要。只有实际存在且可解析的副本显示保留标识。取消订阅仍删除工坊管理的安装副本，但独立副本不匹配卸载文件名并继续保留。
- 失败/取消的面板任务可单项清理：校验文件属于客户端下载目录且不是链接，移至回收站成功后删除记录。文件锁定或移除失败时记录保留。导入失败与工坊失败仅删除记录；「清理已结束」继续只清历史。
- `safehouse:downloadsChanged` 用于字节进度，避免每次进度变更都执行库扫描。任务状态变化仍正常刷新完整状态；后台空闲轮询不再无条件触发刷新。
- `npm run smoke:localization` 使用临时游戏目录和模拟 Steam 接口，验证单项/批量本地化、取消订阅保留、模拟 Steam 清理、重启恢复、失败下载回收站清理及原始导入文件保留。

## 翻译可靠性（0.1.12）

- `core/translator.js` 优先使用必应的公开网页翻译服务，失败时切换 Google；必应的临时网页验证参数只保存在内存中，由 Electron 会话维护该服务的 Cookie，不要求登录或保存账号凭据。
- 通过 Promise 总时限和 AbortController 同时约束整个请求，包括响应正文；长文按段处理并共享总时限，两路分段并发。默认最多等待 12 秒，搜索关键词沿用 4.5 秒预算。相同文本的并发调用复用请求，成功结果保留兼容的本机缓存；失败服务退避 30 秒，手动重试可立即重新连接。
- 卡片标题完成后局部更新；详情标题与说明分别展示，部分失败不丢弃成功译文，失败时可重试及查看原文。关闭和切换详情使用请求标识丢弃过期结果。
- `npm run smoke:translation` 使用真实 Electron IPC 和模拟的服务响应验证标题即时显示、详情翻译、原文切换、失败重试、部分成功和过期结果隔离；`tests/translation.test.js` 覆盖服务切换、缓存、总超时、响应正文卡住、长文及重试恢复。

## 我的收藏与分页（0.1.13）

- `core/favorites.js` 只保存经过校验的公开元数据快照，`favorites.json` 与版本目录分开。收藏没有 Steam 操作和游戏文件操作依赖，移除记录不调用取消订阅、卸载或任务清理。写入失败不更新内存；相同项目重复收藏不生成副本。
- 工坊卡片和详情提供收藏；收藏页只展示已收藏内容。复用工坊标签与本地资源优先的分类依据，支持大类、细分类、具体替换目标、本地双语别名搜索及每页 30 项。收藏详情先显示保存信息，远程详情不可用时保留快照。
- 页码可点击或输入回车跳转。单一查询使用社区真实页码；社区有总页数时显示并校验。双语会话连续合并去重，大跨度跳转直接从所选社区页建立新游标，不预取中间所有页面；已展示页缓存保持返回稳定。没有可靠总页数时不估造总数。
- 整页标题翻译独立于搜索返回，不占用界面的操作锁；旧页的后台结果不会覆盖新页。`smoke:favorites` 在翻译请求始终等待时验证下一页、数字按钮、输入跳转和收藏，并用临时 VPK 验证移除收藏后安装、启停与订阅保持。

## 控制台登录保持（0.1.14）

- 启动前显式将 `userData` 和 `sessionData` 固定到 `%APPDATA%\Safehouse`；测试覆盖目录使用 `SAFEHOUSE_DATA_DIR`，两个路径始终一致。保留既有 `persist:safehouse-center-console` 分区，不复制、清空或重建用户 Cookie。
- 当前 L4D2-Control 服务端会话驻内存，管理员八小时、普通账号二十四小时到期；服务端重启后即使 Cookie 存在也会无效。客户端不能通过重复写入 Cookie 延长或恢复服务端会话。
- `core/console-login.js` 实现显式勾选的账号保存：仅适配 `/login`、`/login.html` 的两个已有登录表单，通过当前隔离会话提交正常登录请求；确认成功并验证 `/api/auth/session` 后，才用 Electron 异步 safeStorage 系统加密保存。未勾选、注册及 HTTP Basic 继续由原面板处理，不采集这些表单的密码。
- `console-logins.json` 仅包含版本、来源 SHA-256 索引和系统密文；账号、密码及完整来源都在密文内。来源按协议、域名、端口隔离；记录不进入 settings、下载历史、日志或 Git。无法使用系统加密时不回退到明文。
- 登录页出现时先验证现有会话，有效则不发送密码；无效且存在明确保存的记录才重新认证。失败每分钟最多一次，账号被拒绝即删除保存；网络失败保留密文供稍后手动重试，不循环撞登录。
- 面板退出登录请求、退出标记 Cookie 和本人修改密码请求立即清除当前来源保存；取消正在执行的登录，禁止延迟响应重新保存。工具栏“忘记登录”清除保存但保留当前 Cookie 的正常生命周期。网页没有解密接口、通用 IPC 或 Node 访问。
- `npm run smoke:console-login` 使用临时账号和内存服务端，验证 Cookie 跨进程、真实系统加密、普通/授权登录、服务重启恢复、来源隔离、主动退出、忘记登录与改密码后停止重试。设置 `SAFEHOUSE_UPGRADE_FROM_BIN` 可从旧发布程序登录后升级验证；`SAFEHOUSE_RELOCATED_BIN` 可验证换 EXE 路径后的密文恢复。

## Steam、下载和翻译的实际行为

管理器启动后直接读取本机 Steam 安装目录下的 `config/loginusers.vdf`，显示最近使用的本地账号。Steam 未运行时可以从设置页打开 Steam；管理器不要求输入密码、不嵌入 Steam 登录页，也不保存网页会话。

工坊卡片和详情提供「订阅」「重新下载 / 更新」「取消订阅」，当前页面显示 Steam 返回的真实字节进度。通过 Steamworks UGC 使用本机正在登录的账号；Steam 必须运行且该账号拥有求生之路 2，不需要管理器网页登录或 Steam Web Cookie。Steam 完成下载后，管理器校验 VPK 并复制到游戏 addons，命名为 `safehouse-workshop-工坊ID.vpk`。L4D2 的 `_legacy.bin` 同样按 VPK 结构校验，不按扩展名盲信。安装完成才标记完成；等待阶段不伪造进度。取消订阅会停止任务并卸载对应本地副本。重复安装相同文件不重复复制，遇到不同内容的同名文件保留现有文件并显示失败。

社区请求和必应 / Google 翻译服务需要网络。翻译只发送输入的搜索词或所选社区公开文字，结果保存在本机；服务不可用时保留原文并显示错误。工坊公开内容的可见性取决于 Steam 社区网络状态。常规自动化验证使用临时游戏目录和模拟账号状态；`node tests/workshop-live.cjs` 为真实 Steam 集成验证，会临时订阅指定的小体积公开项目并在结束时取消新增订阅，只安装到临时游戏目录。

## 首版边界

- 安装支持完整单文件 VPK 或含 VPK 的 ZIP；单次 1–100 个输入，单文件最大 2 GiB，ZIP 总解压上限 4 GiB。拒绝目录穿越、链接、加密 ZIP 与包内可执行文件。RAR、7z、裸 BSP 和 SourceMod 插件暂不支持。
- Steam 原始缓存只读；从管理器下载的 VPK 会单独安装到 addons 后提供启停与卸载。分卷 VPK 可在分卷齐全时读取，但不支持从管理器安装或卸载。
- 应用不提供冲突检测页面；启停管理针对实际 `addonlist.txt`，损坏 VPK 会单独提示。
- 启停与卸载后，在游戏下一次加载内容时生效；游戏运行期间可能占用文件。
- 首版界面为中文，社区翻译目标可以跟随其他系统语言。提供手动检查和确认安装更新；暂没有 GameMaps、配置导出与云同步。

## 数据与恢复

设置、安装记录和翻译缓存保存在 `%APPDATA%\Safehouse`。Steam 账号状态只读取本机 Steam 文件，不复制账号凭据。开发/测试可用 `SAFEHOUSE_DATA_DIR` 指定独立目录。卸载的文件可在 Windows 回收站恢复；安装源文件始终保留。清理已结束任务只删除队列记录，不删除已安装内容。

应用运行副本通常位于 `%LOCALAPPDATA%\Safehouse\versions`；旧缓存不可写时改用 `%TEMP%\Safehouse-runtime\versions`，该运行副本可由启动器重新生成。开发运行时缓存位于 `%LOCALAPPDATA%\Safehouse\runtime`。这些目录与游戏内容和永久设置目录分开。

## 安装版与客户端更新（0.1.15）

- `scripts/pack.cjs` 从同一应用生成 NSIS 安装版和原生启动器便携 ZIP。安装包为当前用户安装，`scripts/installer.nsh` 固定当前用户选项；不包含提权安装选项。
- 仅安装版含 `resources/safehouse-installed.json`。两种发行模式都使用原有固定 `%APPDATA%\Safehouse`，安装目录和更新缓存不存放设置、收藏或登录信息。
- `core/updates.js` 包装 `electron-updater` 的 `NsisUpdater`，由明确的 IPC 检查、下载、取消及安装。禁用自动下载、退出自动安装、降级、预发行和 Web 安装器；完整下载后验证 SHA-512，不通过则禁止安装。
- 正式 feed 为 GitHub `Z1og/Safehouse` Releases，每次发布必须上传 `latest.yml` 及其指向的安装 EXE。保留便携 ZIP 与两个 SHA-256 文件，源码不会含私人更新令牌。
- 安装版更新指定当前安装目录；便携版更新会转为安装版。旧于 0.1.15 的客户端需首次手动下载安装器。`偏好设置 → 应用更新` 显示真实版本、进度和错误；普通退出不安装。
- 安装前检查文件操作、工坊和面板下载队列，并刷新控制台会话。卸载保留数据，不移除游戏内容；服务器主动退出、会话失效和账号密码变更仍按原认证规则处理。
- `npm run smoke:updates` 使用真实 Electron / NsisUpdater 与临时 HTTP feed，覆盖无更新、网络错误、重试、取消、进度、SHA-512 失败、安装 IPC 保护和 980px 界面。下载 fixture 只验证校验流程，绝不执行。
- `SAFEHOUSE_INSTALLER_APP` 指向已有打包应用后，`npm run smoke:installer` 构造隔离的前一版本与当前版本安装器，验证实际安装、客户端内下载并升级、原目录重启与卸载。使用独立 appId、`SafehouseUpdateTest.exe`、快捷方式、用户数据、游戏目录和更新缓存，避免关闭真实客户端；测试包版本标记仅供集成测试。

## 开发与验证

在 `desktop` 目录运行（Node.js 22 或更新版本）：

```powershell
npm ci
npm start
npm test
npm run smoke
npm run smoke:renderer
npm run smoke:taxonomy
npm run smoke:console-search
npm run smoke:panel-download
npm run smoke:console-login
npm run smoke:server-connection
npm run smoke:translation
npm run smoke:favorites
npm run smoke:updates
npm run pack
```

`npm start` 自动准备本机运行时，解决当前工程路径下的启动问题。`npm test` 使用临时目录验证核心模块；`smoke` 启动真实 Electron，通过桌面 IPC 验证启停、VPK / ZIP 安装、重复拒绝、回收站卸载、主题与重启恢复；`smoke:renderer` 使用系统 Chrome / Edge 与测试接口验证渲染和账号状态切换。界面截图放在 `desktop/output/playwright`。

发布包生成在项目 `outputs/desktop`，包含安装 EXE、便携 ZIP、各自 SHA-256 和 `latest.yml`。发布前需核对 feed 中的安装器文件名、版本及 SHA-512；正式上传必须带上 `latest.yml`。可用 `SAFEHOUSE_ELECTRON_BIN` 指定运行时；验证已打包程序时另外设置 `SAFEHOUSE_PACKAGED=1`。

`npm run pack` 需要 Windows 和 Zig 原生编译器。将 `SAFEHOUSE_ZIG_BIN` 设置为 `zig.exe` 的绝对路径，或放置于 `%LOCALAPPDATA%\Safehouse\build-tools\<Zig目录>\zig.exe`。打包时使用系统 `icacls.exe` 修正自有发布 EXE 的完整性级别，失败会终止构建；不会要求管理员权限。
